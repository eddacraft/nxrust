# v0.1 Shakedown

Prove the plugin end-to-end on a real consumer (anvil), ship the first
npm release, and close out anvil's outstanding `NXRUST-*` and
`RUSTNX-004/005` work items.

## Purpose

The nxrust plugin is feature-complete for v0.1: seven executors, five
generators, a working `createNodesV2` + `createDependencies` graph
plugin, a unit-test suite, and two rounds of council + adversarial
review addressed. What it has **not** done yet:

1. Been driven end-to-end against a real Rust crate in a real Nx 22
   workspace outside this repo
2. Shipped to npm
3. Replaced the in-repo `tools/nx-rust/` copy in anvil-001

Until all three of those land, the plugin is theoretical. This module
closes that gap.

**Why this matters:**

1. **Anvil RUSTNX depends on this.** RUSTNX-004 and RUSTNX-005 in
   `plans/modules/rust-nx-migration.aps.md` (anvil) are waiting on a
   working plugin. Anvil is currently pulling from a pnpm workspace
   link into `tools/nx-rust/` — fine in-repo, but it means anvil cannot
   update its Nx version independently of this plugin.
2. **Monodon is not coming back.** The anvil NXRUST plan already
   documented the monodon rejection. Shipping nxrust under Apache-2.0
   gives the wider Nx-plus-Rust community a maintained alternative.
3. **Review findings need real-world validation.** The adversarial
   reviewer flagged `target/` caching and `cargo metadata` performance
   as "unverified until pilot". Pilot verifies them.

## In Scope

- Smoke-test the plugin end-to-end: install it into anvil-001 via pnpm
  workspace protocol (already in place), run one pilot crate through
  the full executor set, assert cache hit on second run
- Roll the pilot shape out to the remaining 8 anvil crates
- CI smoke test in this repo (nxrust): build + run all unit tests + run
  the pilot executor against a fixture crate held inside `e2e/`
- Add a dependent-repo smoke in anvil's `rust.yml` that runs
  `pnpm exec nx run anvil-kernel-types:check` against the linked plugin
- First npm publish of `@eddacraft/nx-rust@0.1.0` (or chosen scope)
- Anvil switches from `workspace:*` link to the published version;
  anvil's `tools/nx-rust/` directory is removed
- Anvil's `plans/modules/rust-nx-migration.aps.md` RUSTNX-004 and
  RUSTNX-005 intents updated to name this published package; anvil's
  `plans/modules/nx-rust-plugin.aps.md` NXRUST-005/006/007/008 marked
  Complete with pointers back to this module

## Out of Scope

- Adding any new executor or generator beyond what already exists in
  `src/executors/**` and `src/generators/**`
- `napi`, `wasm-pack`, `preset`, `add-napi`, `add-wasm` — monodon-parity
  items deferred to module `02-monodon-parity`
- `cargo-nextest` executor, `bench` executor, glob edge cases in
  workspace-member detection — deferred to module `03-v0.2-polish`
- Cross-compile matrix changes in anvil — stays in anvil's `rust.yml`
  per RUSTNX constraints
- `crates.io` publishing — the `release-publish` executor exists and is
  unit-tested; it stays "unvalidated against a real token" until a
  consumer exercises it

## Interfaces

### Depends On

- `@nx/devkit ^22.6.5` (already in `package.json`)
- A real Nx 22 consumer workspace to pilot against (anvil-001 is the
  chosen pilot)
- npm publish credentials for the `@eddacraft` scope (or the chosen
  scope) — needed only at R4

### Exposes (at the end of this module)

- `@eddacraft/nx-rust@0.1.0` on npm
- A dependent-repo smoke job in anvil's `rust.yml` that fails loud if a
  nxrust release breaks anvil
- Anvil's `project.json` files across all 9 crates using this plugin's
  executors

## Constraints

- **Zero regressions on anvil.** Every `cargo check/test/clippy/fmt`
  call that passes today must still pass after the plugin wraps it. If
  the pilot shows a regression, the pilot reverts — it does not press
  on.
- **No code changes to nxrust during pilot** unless the pilot exposes a
  real defect. "Cosmetic" or "while we're here" edits wait for v0.2.
- **Anvil switchover happens in one PR**, reversible with a single git
  revert. Do not interleave the switchover with unrelated anvil work.
- Published package ships `LICENSE`, `README.md`, `CHANGELOG.md`,
  `dist/**`, and the top-level `executors.json` / `generators.json` —
  nothing else.

## Work Items

### NXRUST-R1: Pilot on `anvil-kernel-types` [Complete: 2026-04-21]

- **Intent:** Drive the full plugin end-to-end against the smallest
  real crate before touching any of the others
- **Expected Outcome:** anvil's `nx.json` registers `nxrust` as a
  plugin; `pnpm exec nx run eddacraft-anvil-kernel-types:<target>`
  matches `cargo <cmd> -p eddacraft-anvil-kernel-types` for
  check/test/clippy/fmt-check; second local run reports cache hit;
  `nx graph --focus=eddacraft-anvil-kernel-types` renders the correct
  edges
- **Scope:** anvil-001 — `nx.json` (register plugin), root
  `package.json` + `pnpm-lock.yaml` (add nxrust dev-dep)
- **Validation:** All four checks in Expected Outcome pass
- **Confidence:** medium
- **Risks:** `target/` caching is notoriously fragile. If the second
  run rebuilds instead of cache-hitting, narrow the `outputs`
  declaration on the affected target (cache test/clippy reports, not
  raw build output) rather than abandon the cache.
- **Non-scope:** Any of the other 8 crates
- **Resolution:** Linked nxrust into anvil on branch `nxrust-pilot-r1`
  via `pnpm add -Dw nxrust@file:../../nxrust`; registered `{"plugin":
  "nxrust", "options": {}}` in anvil's `nx.json` plugins array;
  `pnpm exec nx show projects` now lists all 9 Rust crates alongside
  TS projects. Ran check (3.09s cold → cache hit on re-run), test
  (9 tests passed), clippy (clean), fmt-check (clean). Graph focus
  confirmed: `eddacraft-anvil-kernel-types` has no outgoing edges
  (leaf), and 4 dependents (`eddacraft-anvil-kernel`, `anvil-bench`,
  `eddacraft-anvil`, `eddacraft-anvil-tui`). No plugin defects
  surfaced. Two plan-vs-reality reconciliations captured: (a) Cargo
  package names in anvil are prefixed `eddacraft-` so Nx project keys
  follow suit; (b) the plugin auto-infers projects from Cargo.toml —
  no manual `project.json` files needed.

## Risks & Mitigations

| Risk | Impact | Likelihood | Mitigation |
|------|--------|------------|------------|
| Pilot exposes a defect that forces nxrust code changes mid-module | medium | medium | That's the point of the pilot — patch nxrust, re-link, keep going. Do not let "no code changes during pilot" become "suppress real defects". |
| npm scope (`@eddacraft`) not registered | medium | low | Verify before R4; fall back to unscoped `nxrust` if the scope is unavailable |
| Anvil switchover PR pulls in unrelated changes | low | medium | Keep R5 to one PR, scoped strictly to package.json + lockfile + tools/nx-rust deletion |
| `target/` caching defeats the affected story on rollout | high | medium | Narrow `outputs` on a per-target basis; cache reports not binaries where binaries embed absolute paths |

## Decisions

- **D-M1:** Pilot first on `anvil-kernel-types` (smallest, no internal
  deps) rather than `anvil-kernel` (touches everything). *Accepted —
  matches anvil NXRUST-005 rationale.*
- **D-M2:** Publish and consume via npm, not via git ref. Git refs work
  but hide drift. *Accepted.*
